## 5. 历史重写操作要点（如需再次执行）

1. **备份先行**：`git bundle create <备份路径>.bundle --all` → `git bundle verify <备份路径>.bundle` 确认完整；
   备份文件移至持久目录（示例：`<USER_HOME>\backups\`），勿留 %TEMP%。
2. **获取工具**：git-filter-repo 为单文件 Python 脚本（官方仓库 main 分支，约 210 KB）；
   pip 安装失败时经代理下载 raw 文件，用 Python 3.8+ 直接运行（`python <脚本> --version`）。
3. **fresh clone**：`git clone --no-local <仓库路径> <临时克隆路径>`（`--no-hardlinks` 不满足 fresh 判定）。
4. **重写**：
   ```
   python <filter-repo脚本> --force --path "<敏感文档1>" --path "<敏感文档2>" --invert-paths \
       --replace-text <规则文件> --refs main
   ```
   - 规则文件格式：每行 `敏感串==>占位符`（literal 匹配，`==>` 分隔；宽泛串须排在精确串之后）；
   - `--invert-paths` 删除指定路径历史；`--refs main` 限定只重写 main；
   - 补充规则后重跑幂等（占位符不含原模式，不会二次替换）。
5. **同步回原仓库**（全程禁 `reset --hard`）：
   ```
   git fetch <临时克隆路径> main:refs/heads/main-filtered
   git update-ref refs/heads/main refs/heads/main-filtered
   git branch -D main-filtered
   git restore --source=HEAD --staged --worktree .
   ```
6. **验证三件套**：敏感 grep 零命中 + 目标文档历史零输出 + build/vet/test 全绿。
7. **清理**：临时克隆与规则文件删除（规则文件含敏感串，用后即删）。

## 7. 风险与注意事项

1. **force push 纪律**：Git 全局规则"严禁 force push / reset --hard"始终适用；
   目标仓库任何意外内容出现即停止上报，不覆盖。
2. **本地保险分支**：`backup-main-raw`（原始历史）、`backup-local`、`release-clean`
   分支保留本地；推送前确认这三者不随推送暴露（本地分支不入库，无泄露）；
   `backup-local` 含早期测试文档历史（构造性数据），若未来需要推送须另行处置。
3. **凭据安全**：gh 认证 token 存系统 keyring；remote 用 HTTPS URL 无内嵌凭据；
   不创建 .netrc；推送全程使用内置凭据管理器。
4. **二进制盲区**：evidence 内 png 截图与 .gz 压缩包无法被文本 grep 覆盖，
   推送后验证清单第 4 项人工抽查兜底（低概率）。
5. **排除项政策**：`config.exclude_ips` 为操作方自身 IP 白名单，**不脱敏**
   （用户裁定 2026-08-18，AGENTS.md 规则）；审计/扫描不得标记为泄露。
6. **备份保留**：bundle 备份与本地保险分支保留至推送完成并确认远程无误后
   方可清理；清理 bundle 前再次 `git bundle verify`。
