# sentry-agent 部署手册（M4，用户自行在 VPS 执行）

- 交付：`deploy/` 目录（Dockerfile、docker-compose.yml、config.json 模板、5 个部署脚本）
- 关联：`docs/技术方案.md` 第 6 章（部署设计）、第 7 章（磁盘与水位）
- 前置：VPS（1C1G 基线，Debian/Ubuntu 或 RHEL 系/Alpine）、root 权限、公网或内网可达

## 1. 快速部署（推荐路径）

```bash
# 1) 获取部署资产（git clone 或 scp 传输 deploy/ 目录与镜像）
# 2) 环境检查（FAIL 项必须处理后重跑）
sudo bash deploy/check_env.sh
# 3) 一键部署（检查→系统配置→fail2ban→防火墙规则→数据目录→compose 启动）
sudo bash deploy/deploy.sh
# 4) 健康检查
docker ps --filter name=sentry-agent
curl -s http://127.0.0.1:8080/api/v1/health
# 5) 访问面板（方式参考第 6 节；默认仅本机回环）
# 安全基线：部署前后执行 §1.1 P0 四条检查——面板访问通道形态（P0-1）应在部署前确定
```

镜像获取：`docker build -t sentry-agent:latest -f deploy/Dockerfile .`（本机构建，debian 基础镜像实测压缩后 42.65MB，<50MB 达标）
或离线导入：`docker load < sentry-agent.tar.gz`（C-14 不可达时）。

## 1.1 部署前安全基线检查（P0 四条，AUD-VPS-001 §6 P0）

以下四条为部署纪律红线，**全部满足后**才允许将面板投入实际使用；对应复验项见 `docs/M4_VPS复验清单.md`（P0-1~P0-4）。

1. **面板访问通道红线**：面板仅允许经 SSH 隧道（推荐）或带鉴权（Basic Auth/客户端证书）的反代访问；**任何公网直接暴露（含 `web.listen=0.0.0.0`）视为高风险配置**，须先落地独立鉴权层（对应攻击路径 #1-#3）。
2. **数据目录权限收权**：部署后执行 `chmod 700 /var/lib/sentry-agent && chmod 600 /var/lib/sentry-agent/state.db`（配合代码级权限修复 DEV-P1-001；多用户 VPS 防止其他本地用户读取 SSH 指纹/用户名/防火墙日志等敏感数据）。
3. **宿主防火墙默认拒绝**：确认宿主防火墙默认策略为拒绝（INPUT DROP），仅开放 22（+面板隧道源 IP 白名单），并持久化规则（`setup_firewall.sh` 仅插 LOG 不设策略；空环境部署无默认拒绝时全端口开放）。
4. **SSH 加固**：`/etc/ssh/sshd_config` 设置 `PasswordAuthentication no`（仅密钥认证）；确认 fail2ban sshd jail active（`fail2ban-client status sshd`）。

## 2. 部署脚本与分支指引

| 脚本 | 职责 | 分支/失败处理 |
| :--- | :--- | :--- |
| `check_env.sh` | C-01~C-14 环境检查（发行版/内核/systemd/journald/conntrack/虚拟化/防火墙后端/fail2ban/磁盘/内存/sshd/日志源/Docker/镜像网络） | FAIL 项终止；BRANCH 项按指引 |
| `setup_system.sh` | journald（persistent + RateLimit 5s/5000 + 4G 上限）、sshd LogLevel VERBOSE、logrotate rotate 9999；回读校验 | dry-run 默认，--apply 写入 |
| `install_fail2ban.sh` | fail2ban 安装（6.5.4：安装/后端对齐/sshd jail/日志 ACL/试封回滚） | 后端与 C-07 不一致 → B6 人工决策 |
| `setup_firewall.sh` | 模式 B：现有 DROP 规则前插入 SENTRY_FW 限速 LOG（5/s 突发 10，零策略变更） | --rollback 回滚；nft/iptables 双后端 |
| `deploy.sh` | 总入口（1→5 顺序执行 + compose 启动 + 健康检查） | 每步失败可独立重跑 |

分支对应方案 6.2：
- **B1**（无 systemd）：`ssh.source=rsyslog`（auth.log）+ `fw.source=kmsg`（/dev/kmsg，需特权挂载）；容器挂载 auth.log/kern.log 文本文件（B7 联动）
- **B2**（journald 非持久）：setup_system.sh 写 persistent 并重启 journald
- **B4**（内核 <3.10）：警告继续，V1 在目标环境重跑
- **B5**（conntrack 不可用）：agent 自动降级 ss 快照近似（system_event 留痕；面板标注"近似通道"）；容器形态需 `--network host`（compose 已配置）
- **B6**（fail2ban 后端不一致）：人工对齐（方案 6.2 拒绝自动切换）
- **B8**（Docker 不可用）：裸机 systemd 部署（见第 7 节备选）

## 3. 配置项要点（deploy/config.json）

| 项 | 默认 | 说明 |
| :--- | :--- | :--- |
| `ssh.source` | journald | B1 环境改 rsyslog |
| `fw.source` | journald-kernel | B1 环境改 kmsg |
| `web.listen` | 127.0.0.1:8080 | 改 0.0.0.0 时暴露面自担（D-03）；WS 将拒绝无 Origin 请求（M-02） |
| `web.ws_origin_allow` | http://127.0.0.1:8080 | 反代/改 listen 时同步修改（否则 WS 403，见下方说明） |
| `disk.*` | 80/90/95 | 磁盘三级告警与归档跳过阈值（共用配置） |

### WS Origin 配置与防护边界（VS-06/VS-10）

**反代场景必须同步修改 `web.ws_origin_allow`（VS-06）**：默认白名单为 `http://127.0.0.1:8080`。使用反向代理（域名/非 127.0.0.1 访问）时，浏览器页面的 Origin 变为实际访问地址（如 `https://panel.example.com`），与白名单不一致 → WS 升级请求被 403（前端自动降级为轮询，实时推送失效）。示例：

```json
{ "web": { "listen": "127.0.0.1:8080", "ws_origin_allow": "https://panel.example.com" } }
```

**Origin 防护边界声明（VS-10）**：WS Origin 白名单仅防"浏览器跨站"场景（恶意网页 JS 连 WS 携带其自身 Origin，与白名单不符被拒）。回环监听（127.0.0.1）下，**无 Origin 头的非浏览器客户端（curl/脚本）在 allowNoOrigin 逻辑下可直连**——因此 WS 防线的有效性依赖"面板仅回环监听 + 隧道访问"部署纪律（P0-1）；一旦面板经反代/隧道对外可达，Origin 白名单不能替代访问控制，须前置鉴权。

## 4. 告警响应（system_events 各级别）

| 级别 | 来源 | 响应 |
| :--- | :--- | :--- |
| error | disk（emergency） | 立即扩容或清理（**绝不自动删除数据**，D-04）；归档已跳过 |
| warn | disk（critical） | 归档跳过中；规划扩容（默认档 ≥80GB） |
| warn | conntrack（溢出/R-10） | 攻击高峰正常；netlink 缓冲已自动扩容至 8MB 上限 |
| warn | f2b（查询失败） | fail2ban 库不可读（检查 ACL/group_add） |
| error | store | agent 已退出（systemd/docker restart 自动拉起）；检查磁盘与主库权限 |

## 5. 扩容指引

- **磁盘**：永久保留口径（D-04），磁盘随运行线性增长；默认档 ≥80GB 对应一年数据+压缩副本；超过后扩数据卷或调整 `archive.copy_after_days`
- **内存/CPU**：1C1G 基线达标（实测采集端 RSS 峰值 ~19MB）；全栈含 fail2ban 上界超标为已接受取舍（D-02）
- **数据迁移**：归档副本（.db.gz）解压后可离线回溯；主库直接拷贝需停 agent（WAL 一致性）

## 6. 面板访问方式（工具不内置，用户自配——D-03）

1. **SSH 隧道（零公网暴露，推荐）**：本机 `ssh -L 8080:127.0.0.1:8080 user@vps` 后访问 `http://127.0.0.1:8080`；可配 autossh 保活
2. **反向代理 + TLS**：Nginx/Caddy 反代 127.0.0.1:8080 并加 HTTPS（示例见下）
3. **直接暴露**：`web.listen=0.0.0.0:8080`（无鉴权，仅适合内网可信环境，暴露面自担）

```nginx
# Nginx 反代示例（TLS 由 certbot 等签发）
server {
    listen 443 ssl;
    server_name panel.example.com;
    ssl_certificate     /etc/letsencrypt/live/panel.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;   # WebSocket 支持
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```

## 7. 裸机 systemd 备选（B8 回退路径，方案 6.3）

```ini
# /etc/systemd/system/sentry-agent.service
[Unit]
Description=Sentry Agent - lightweight security posture collector
After=network.target systemd-journald.service
Wants=network.target
[Service]
Type=simple
User=sentry
Group=sentry
ExecStart=/usr/local/bin/sentry-agent --config /etc/sentry-agent/config.json
Restart=on-failure
RestartSec=5
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/var/lib/sentry-agent
PrivateTmp=yes
ProtectHome=yes
[Install]
WantedBy=multi-user.target
```
权限注意：journald 流式读取需 systemd-journal 组（`SupplementaryGroups=systemd-journal`，C-12 实测调整）。

## 8. 运维要点

- **日志**：`docker logs sentry-agent`（json-file 10m×3）；宿主日志按 logrotate rotate 9999 保留
- **多 LOG 规则重复计数语义（D-05 设计固有，DEV-009 注明）**：模式 B 在多条 drop/reject 规则前各插一条 LOG——同一连接若命中多条 LOG（如 fail2ban ban 规则 + 用户规则均在前）会被多条 LOG 记录，攻击端口统计（top_ports）为采样视图，命中次数可能大于实际连接数；面板已标注采样性质，属设计内行为
- **备份**：主库永久保留（D-04）；副本由归档模块按月生成（gzip）；建议定期将 archive 目录异地拷贝
- **升级**：重建镜像 → `docker compose up -d --build`；数据卷不动；schema 变更需版本化迁移（当前 schema_version=1）
- **VPS 部署后**：务必执行 `docs/M4_VPS复验清单.md`（P0-1~P0-4 安全基线 + V-01~V-08 等共 21 项，其中 D-09/read_only+f2b WAL 等标注"需 VPS 实测"），完成结论回传
