## 6. 已知限制与遗留

- connections 表 IPv6 列为本轮补充（方案 4.1"IPv6 存 TEXT"落地，方案 4.2 DDL 已同步）；ssh/fw 事件结构无 IPv6 字段（M1 记录限制，M2 保持——VPS 场景 IPv4 为主，如需扩展在 M3 API 层评估）
- schema_version=1 的库结构变更：M2 未对外发布，无迁移需求；M4 交付前若有结构变更需版本化迁移
- QueryBanned 依赖 fail2ban 库结构（bans 表）；WSL 无 fail2ban 的环境以失败留痕验证（真实库联调列入 VPS 复验）
- 退出边界披露（reviewer R-15）：①main.go 60s 退出超时兜底——极端积压（写路径持续满载超 60s）时强制结束可能违反零丢失承诺，触发条件未量化；②archiver 协程不在 producers WaitGroup——ctx 取消瞬间其 system 告警 send 可能被排空竞态丢弃（极低概率、仅丢一条告警）
- 磁盘水位检查（方案 3.9"critical 跳过归档"）最小形态已实现（A-02：归档前 statfs 检查，使用率 ≥90% 或 statfs 失败 → 跳过并 warn 留痕）；**归档失败仅记录不退出**（方案 3.9 容错语义，reviewer N-01 修正——归档失败 ≠ 主库写失败，A-01 的退出语义仅限 Run 主写路径）；完整水位模块（warn/emergency 分级与 diskMonitor 协程）M3 补
- 归档执行记录：`TestExecArchiveSystemEvents`（Linux 集成测试，WSL 通过）：归档开始/完成 info 留痕（含耗时）、失败 error 留痕含耗时（reviewer N-05 补记）
- kmsg 时间戳口径：kmsg 头部内核单调时间与 Unix 时间不可直接换算，M2 采用接收时刻近似（event.go 口径注释已说明）
- RunArchiver 单周期最多回扫 24 个月（archive.go 注释）：超 24 个月极端积压的月份需后续周期滚动追赶；archiveReq 队列容量 8，首个周期最多消化 8 个月，幂等保证无重复归档，仅归档追赶有延迟（reviewer N-02/N-05）
- 归档副本掉电边界：gzip 落盘已加 fsync（N-01 修复）；与主库 synchronous=NORMAL 的掉电风险级别相当，进程中断路径（.tmp/半截）自愈闭环
- **存储故障路径（DEV-004 A-01 补记）**：`st.Run(ctx)` 返回 error 时（运行中数据写入失败）main 向 stderr 输出 `致命错误: 存储模块退出（数据写入失败）` 并 `os.Exit(1)`——选择 os.Exit 而非 cancel 受控退出的理由：①M4 systemd 服务 Restart=on-failure（方案 6.3）依赖非零退出码触发重启；②存储不可写时继续运行只会产生数据空洞；③Run 内部 defer 已关闭数据库连接，无资源泄漏。实测证据：①初始化故障（`scripts/m2_a01_fault_test.sh`，db.path=/dev/null 与 /proc/state.db → 退出码 1 + stderr 明确错误）；②**运行中写失败**（`scripts/m2_a01_runfault_test.sh`，2M tmpfs 配额 + SYN flood 注入填满 → SQLITE_FULL → Run 返回 error → stderr `致命错误: 存储模块退出（数据写入失败）: 批量提交失败: 提交事务失败: database or disk is full (13)` + 退出码 1）。故障可观测性满足方案 7.3（不依赖 system 通道——故障时消费端即 Store 自身已不可用）。
- **D-09 覆盖率核算（DEV-004 补记，证据 `docs/verification/evidence/m2/fw_cover_linux_after.txt`）**：WSL（Linux）实测 `go test ./internal/fw/ -cover`：全语句 40.7%（Run*/IO 循环豁免，与 TEST-001 §2.2 口径一致）；kmsgSeq 0%→100%。纳入函数核算：ParseFWLine 92.9% / ipToUint32 90% / atou16 75% / kmsgSeq 100%——算术平均 89.5%（精确，达标兜底口径），语句加权估算 ≈92.7%（权重为各函数行数估算：ParseFWLine ~50 / ipToUint32 ~17 / atou16 ~6 / kmsgSeq ~20，cover -func 不输出语句数，加权为估算），两种口径均 ≥80% ✅；TEST-001/TEST-002 的 D-09 台账更新由 tester 基于最新基线（e9d111a）回归时同步
